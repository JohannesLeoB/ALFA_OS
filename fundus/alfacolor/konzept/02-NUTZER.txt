3a ERSTER START UND EINRICHTUNG

Start: App zum ersten Mal öffnen.
Schritte:
  1. Begrüßung zeigt drei Karten: "Neues Setup", "Vorhandenen Ordner öffnen", "Beispiel ansehen".
     Klick auf eine Karte. Return geht weiter.
  2. Neues Setup: Name eingeben. Gerät wählen:
     Mac 1512 x 982, Mac-Fenster 1280 x 800, iPad 1180 x 820, iPhone 393 x 852 Punkte. [Auftrag]
     Die Gerätegröße ist die Startgröße des Rahmens. Sie lässt sich jederzeit ändern.
  3. Speicherort: Standard "Lokal". "iCloud" nur, wenn angemeldet. [Auftrag: iCloud optional]
  4. Spiegel (optional): Ordner wählen, dessen Inhalt übernommen wird. "Später" überspringt.
  5. Code-Ansicht: Schalter "Code zeigen". Standard aus. [Vorschlag]
  6. Abschluss: leere Leinwand mit einem Rahmen und der Karte "Ziehe eine Datei hierher
     oder füge mit Befehl-V Code ein."
Ergebnis: Leinwand mit einem Rahmen. Setup ist gespeichert.
Was schiefgehen kann:
  - Ordner nicht beschreibbar. Meldung: "Setzkasten darf in diesen Ordner nicht schreiben."
    Aktion: "Anderen Ordner wählen." macOS-Zugriffsdialog: [nicht geprüft].
  - iCloud nicht angemeldet. Option grau. Text: "Bis zur Anmeldung wird lokal gespeichert."
    Aktion: "Lokal verwenden."
  - Abbruch mitten im Setup. Nichts ist gespeichert. Beim nächsten Start beginnt die Begrüßung neu.
    Aktion: "Neu beginnen."
Hilfe der App: Jeder Schritt zeigt, was als Nächstes passiert. Ohne "Fertig" wird nichts geschrieben. [Vorschlag]

3b SAMMELN

Start: Leinwand oder Ablage "Eingang".
Wege:
  - Browser-Lesezeichen: Menü Ablage > Lesezeichen importieren. Auswahl: Safari oder Chrome. [Auftrag]
    Ergebnis: Link-Blöcke im Eingang.
  - Pinterest: Pin-Link auf die Leinwand einfügen (Befehl-V). Bild wird übernommen, wenn erreichbar.
    Technische Anbindung an Pinterest: [nicht geprüft].
  - Screenshot: macOS-Screenshot per Umschalt-Befehl-4 oder Umschalt-Befehl-5. [APPLE-Keys]
    Ablage: Spiegel-Ordner oder Ziehen auf die Leinwand. Speicherort des Systems: [nicht geprüft].
  - Datei: aus dem Finder auf die Leinwand ziehen. Bild wird Bild-Block.
    Textdatei mit Code wird Code-Karte. Erkennung nach Endung. [Vorschlag]
  - Code einfügen: Befehl-V auf der Leinwand. Die App erkennt die Sprache (HTML, CSS, JavaScript,
    React/JSX, Swift, Compose, Dart und weitere). Sprache steht im Kopf der Karte. [Vorschlag]
    Nicht erkannt: Dialog "Als Code oder als Notiz?"
Ergebnis: Neue Blöcke an der Einfügestelle oder im Eingang.
Was schiefgehen kann:
  - Code nicht erkannt. Aktion: "Als Code" oder "Als Notiz" wählen.
  - Link nicht erreichbar. Block zeigt Zustand "Offline" (Abschnitt 5).
  - Gleiches Bild schon vorhanden. Hinweis "Schon vorhanden" mit Verweis auf das Original.
    Aktion: "Trotzdem übernehmen" oder "Vorhandenes zeigen."
  - Lizenz unklar. Markierung am Block (Abschnitt 5).
Hilfe der App: Das Panel zeigt "Quelle" für jeden Block: Browser, Pinterest, Screenshot, Datei oder Code. [Vorschlag]

3d RAHMEN UND GRUNDRASTER ANLEGEN

Start: Rahmen-Werkzeug mit Taste R, oder Menü Neu > Rahmen. [Vorschlag]
Schritte:
  1. Gerät aus der Liste wählen (vier Größen wie in 3a) oder "Eigene Größe".
     Breite und Höhe in Punkten eingeben. Tab wechselt das Feld.
  2. Schalter Hochkant / Querformat. [Vorschlag]
  3. Button "Raster" im Panel des Rahmens öffnet den Raster-Editor.
     Felder: Ränder, Spalten (Anzahl und Abstand), Zeilen. [Vorschlag]
     Live-Vorschau zeigt die Linien im Rahmen. Standardwerte: offen, siehe Abschnitt 7.
  4. Hilfslinien: aus dem Lineal am Rand ziehen. Löschen: Linie anklicken, Entf.
  5. Einrasten: Elemente rasten am Grundraster und an den Kanten ein. [Auftrag]
     Schalter "Einrasten" im Menü Ansicht. [Vorschlag]
  6. "Als Vorlage speichern" im Rahmen-Panel. Die Vorlage erscheint in der Bibliothek unter "Rahmen".
Ergebnis: Rahmen mit Raster, optional als Vorlage gespeichert.
Was schiefgehen kann:
  - Feld leer oder keine Zahl. Feld wird rot. Text: "Bitte eine Zahl in Punkten eingeben."
  - Spalten passen nicht in die Breite. Warnung: "Die Spalten passen nicht in die Breite."
    Aktion: "Breite anpassen" oder "Trotzdem".
  - Rahmen wird kleiner als seine Elemente. Dialog: "Einige Elemente ragen über den Rand."
    Aktion: "Elemente verschieben" oder "Rahmen ändern".
Hilfe der App: Maße in Punkten stehen am Rahmen. Der Raster-Editor zeigt das Ergebnis, bevor es gilt. [Vorschlag]

3e ANSICHTS-MOCKUP AUS GESAMMELTEN STÜCKEN BAUEN

Start: Rahmen auswählen, dann "Mockup beginnen" im Rahmen-Panel. [Vorschlag]
Schritte:
  1. Quelle wählen: Bibliothek (Suche und Filter), Eingang, oder die Palette der App-Elemente
     (Blöcke, Farben, Schriftstufen, Notizen). [Auftrag: Drag and Drop aller Elemente der App]
  2. Ziehen in den Rahmen. Das Element rastet am Grundraster ein. Außerhalb des Rahmens liegt es frei auf der Leinwand.
  3. Feinsteuerung: Pfeiltasten verschieben in Schritten. Umschalt-Pfeil in größeren Schritten. [Vorschlag, Schrittgröße offen]
     Befehl-D dupliziert. Wahl-Ziehen kopiert. [Vorschlag]
  4. Mehrfachauswahl: Lasso oder Umschalt-Klick. [Auftrag]
     Ausrichten-Menü: links, Mitte, rechts, oben, unten, Reihe, Raster, Haufen, gleiche Größe. [Auftrag]
  5. Befehl-G gruppiert. Die Gruppe kann einer Zone zugeordnet werden. [Vorschlag]
  6. Vergleich: Schalter "Raster zeigen" und Vergleichselemente. Das Labor hat das schon. [Auftrag]
Ergebnis: Rahmen mit angeordneten Elementen. Jede Position steht in Punkten im Panel.
Was schiefgehen kann:
  - Element ragt über den Rahmen. Rote Markierung am Rand. Hinweis: "Ragt über den Rahmen."
    Aktion: "Zurück in den Rahmen."
  - Code-Karte zeigt keine Vorschau. Zustand "Fehler" (Abschnitt 5).
  - Falsche Zone oder falsche Position. Befehl-Z.
  - Element kopiert statt verschoben. Wahl-Ziehen kopiert. Das Panel zeigt die Anzahl. [Vorschlag]
Hilfe der App: Die Ebenenliste zeigt die Reihenfolge. Klick auf einen Eintrag markiert das Element im Rahmen. [Vorschlag]

7 OFFENE FRAGEN AN JOHANNES
==========================================================================

1. Bausteine (Symbole): Vectorworks unterscheidet drei Verhalten. Schwarz und grün wirken auf alle
   Kopien. Blau wird beim Platzieren eine Gruppe. Rot wirkt nur auf neue Platzierungen. [Suchauszug, VW-Symbols]
   Soll eine Änderung am Original alle verknüpften Kopien ändern?
   Vorschlag: Ja, Kopien mit Verweis folgen dem Original. Eine Kopie ohne Verweis wird Gruppe und bleibt unberührt.

2. Löschen: Soll Entf in einen Papierkorb "Zuletzt gelöscht" legen, der nur auf deinen Befehl leert?
   Oder genügt Befehl-Z?
   Vorschlag: Papierkorb ohne automatische Löschung. Leeren nur auf deinen Befehl.

3. Ausgeblendete Elemente im Export: Sollen sie fehlen, oder mit ausgegeben werden?
   Vorschlag: Ausgeblendet bleibt im Projekt, fehlt im Export. Pro Token gibt es einen eigenen Schalter.

4. Gesten: Die Mac-Version nutzt Trackpad-Gesten des Systems für Zoom und Verschieben.
   Sketchbook auf dem iPad nutzt Drei-Finger-Wischen für Rückgängig und Wiederholen. Soll das für den iPad-Teil übernommen werden?
   Vorschlag: Mac ohne eigene Drei-Finger-Gesten, da macOS sie nutzt [nicht geprüft]. iPad-Teil mit den Sketchbook-Gesten, sobald gebaut.

5. Tastenkürzel: Sollen die Vorschläge aus Abschnitt 6 gelten?
   Konflikte mit macOS (Befehl-H, Control-Pfeil, Befehl-Leertaste, Umschalt-Befehl-4 und -5) bleiben beim System.
   Vorschlag: Übernehmen. Die InDesign-Spalte vorher gegen die Adobe-Seite prüfen, sobald sie erreichbar ist.
